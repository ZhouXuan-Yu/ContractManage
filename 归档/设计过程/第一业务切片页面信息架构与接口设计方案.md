# 第一业务切片页面信息架构与接口设计方案

> 版本：V1.0
>
> 范围：一期第一条可验收业务切片
>
> 目标：在不重复建设页面和数据的前提下，完成“创建合同 → 保存草稿 → 台账查询 → 详情查看 → 再次编辑 → 审计记录”的闭环。

## 1. 两条硬原则

### 1.1 局部变化影响最小

- 页面只依赖合同系统稳定 API，不依赖数据库表结构或外部系统返回结构。
- 合同类型、交易对方和扩展字段通过独立查询模型提供，类型字段变化不改台账和详情的固定结构。
- 台账、创建和详情共享同一合同摘要/详情模型；字段新增只扩展对应区域，不复制到多个模型。
- 外部主体、文件、审批和 AI 只通过适配层接入，本切片不把第三方字段带入页面。
- 页面动作统一由后端返回权限、状态和前置校验结果，避免前端各页面各自判断。

### 1.2 不冗余

| 信息/能力 | 唯一负责位置 | 其他页面处理方式 |
|---|---|---|
| 合同完整查询和筛选 | 合同台账 | 工作台只提供入口和筛选跳转 |
| 合同完整业务信息 | 合同详情 | 台账只显示摘要 |
| 合同创建和草稿编辑 | 合同创建页 | 详情只提供编辑入口 |
| 合同类型和扩展字段定义 | 系统管理配置 | 创建页读取配置，不复制定义 |
| 交易对方主数据 | 外部主数据系统 | 创建/详情只查询和引用 |
| 合同状态转换 | 后端合同领域服务 | 前端只展示允许动作 |
| 操作审计 | 后端审计服务 | 详情只展示审计结果 |

## 2. 页面结构

```text
合同中心
  ├─ 工作台：指标和待处理事项，提供入口
  ├─ 合同台账：查询、筛选、进入详情、批量操作
  └─ 合同详情：单份合同的查看和业务动作

创建合同：从台账或工作台进入的流程页，不是独立一级导航
```

第一切片不新增交易对方菜单、类型配置菜单或独立审计菜单。

## 3. 合同台账

### 3.1 页面职责

负责定位合同，不负责展示合同全部内容，也不负责编辑复杂合同字段。

### 3.2 列表内容

- 合同编号、合同名称。
- 合同大类、合同类型、合同子类型。
- 交易对方名称和当前合同关系。
- 合同金额和币种。
- 合同业务状态、审批状态、AI 处理状态。
- 签署日期、到期日期、更新时间。

列表字段由后端根据字段权限过滤；敏感字段不因进入列表而绕过字段权限。

### 3.3 查询条件

- 合同编号或名称。
- 合同大类、类型、子类型。
- 交易对方。
- 合同业务状态和审批状态。
- AI 解析/审查状态。
- 签署日期、到期日期和更新时间范围。
- 金额范围。

### 3.4 操作

- 查看详情。
- 新建合同。
- 进入筛选后的台账。
- 允许的批量操作和导出入口预留，但第一切片只实现查询和详情进入。

## 4. 合同创建/草稿页

### 4.1 创建入口

创建来源仍由一期需求定义：模板起草、文件导入、手工录入、外部系统同步。第一切片先实现手工录入和最小模板来源；文件服务和外部同步通过 Mock/适配接口接入，不在页面内自建上传或主体主数据管理。

### 4.2 页面分区

1. **基础信息**：合同名称、合同编号、合同类型、合同子类型。
2. **我方信息**：我方主体、我方角色。
3. **交易对方**：选择外部交易对方、选择当前合同关系、查看当前展示信息。
4. **合同内容**：根据合同类型动态加载扩展字段。
5. **保存区**：保存草稿、取消、返回台账。

第一切片不在创建页重复显示完整审计、审批、AI、履行和收付款模块；这些内容在后续详情页签中承载。

### 4.3 表单规则

- 合同类型和子类型决定扩展字段配置。
- 类型配置变化只影响配置读取和新建表单，不改变已保存草稿的历史配置引用。
- 交易对方选择只保存外部 ID、来源和当前展示快照，不保存完整主档案。
- 草稿允许分步保存；保存时校验当前用户权限和乐观锁版本。
- 提交审批、签署和生效不属于第一切片的保存动作。

## 5. 合同详情

### 5.1 页面职责

负责一份合同的完整业务上下文和下一步动作。详情是后续 AI、审批、签署、履行、变更和附件能力的唯一承载页面。

### 5.2 第一切片显示

- 合同摘要：编号、名称、分类、交易对方、状态、更新时间。
- 基础信息和扩展字段。
- 当前正文/内容版本摘要，暂不实现完整编辑器。
- 当前用户可执行动作：草稿编辑、作废等由状态和权限决定。
- 操作记录摘要和进入完整记录的入口；审计数据由后端查询。

### 5.3 后续页签预留

正文与版本、条款与履行、收付款、智能与审批、附件与变更、操作记录。页签只有存在数据或当前用户有权限时才显示，避免空页面和重复内容。

## 6. 交易对方选择

交易对方不是独立页面，而是创建页中的可复用选择组件，也可在详情中查看关联信息。

### 6.1 统一模型

```json
{
  "source_type": "external_party",
  "external_id": "party-1001",
  "subject_name": "示例公司",
  "subject_nature": "organization",
  "relationship_role": "customer",
  "enabled": true,
  "display_snapshot": {}
}
```

`customer`、`supplier`、`partner` 等是当前合同关系角色，不是合同系统中的独立主体模块。

### 6.2 组件规则

- 支持按名称、编号或主体关系查询。
- 选择后显示必要当前信息和来源。
- 保存关联时使用 `source_type + external_id`，禁止只传名称。
- 主体停用或不可签约时禁止用于新合同。
- 外部系统不可用时不能伪造主体；已保存合同仍可查看历史快照。

## 7. 首批内部 API

### 7.1 合同类型

```text
GET /api/contract-types
GET /api/contract-types/{type_id}/form-schema
```

返回当前用户可用的类型、子类型和动态表单定义。表单定义只描述展示和校验，不替代数据库设计。

### 7.2 交易对方

```text
GET /api/counterparties?keyword=&relationship_role=&page=
GET /api/counterparties/{external_id}
```

合同系统内部统一调用交易对方 Adapter，页面不感知实际来源系统。

### 7.3 合同

```text
POST /api/contracts
GET  /api/contracts
GET  /api/contracts/{contract_id}
PUT  /api/contracts/{contract_id}/draft
POST /api/contracts/{contract_id}/void
```

写操作要求：

- `X-Request-Id`。
- `X-Idempotency-Key`。
- `If-Match` 或等价乐观锁版本。
- 后端从登录态获取操作者，不信任前端传入的用户 ID。

### 7.4 审计

```text
GET /api/contracts/{contract_id}/operation-logs
```

审计写入由后端业务动作自动完成，前端不能自行提交“已完成审计”。

## 8. 页面与 API 的影响控制

```text
类型配置变化
  -> form-schema 变化
  -> 创建页动态渲染变化
  -> 合同保存扩展字段变化
  -> 台账固定摘要和详情固定区不变

交易对方来源变化
  -> Adapter/映射变化
  -> counterparty API 模型不变
  -> 创建页和详情不变

数据库字段变化
  -> Repository/Assembler 变化
  -> API 模型只在确有业务展示需要时变化
  -> 页面按区域局部增加
```

## 9. 第一切片验收

```text
进入合同中心/台账
→ 点击新建
→ 选择合同类型和子类型
→ 选择交易对方及合同关系
→ 填写基础字段和类型扩展字段
→ 保存草稿
→ 返回台账看到合同
→ 进入详情查看
→ 再次编辑并保存
→ 查看操作记录
```

必须覆盖：无权限类型、停用交易对方、重复保存、版本冲突、必填校验失败和重复请求。

## 10. 暂不实现

- 完整文件上传和真实文件服务联调。
- AI 解析和法律审查真实 Provider。
- 外部审批提交和回调。
- 完整正文编辑器、签署生效、履行、收付款和变更。
- 客户/供应商独立管理页面。
- 独立审计菜单和重复的合同详情页面。
