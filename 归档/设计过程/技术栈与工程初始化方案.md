# 通用合同管理系统技术栈与工程初始化方案

> 版本：V1.0
>
> 状态：一期技术基线
>
> 说明：本方案采用已确认的默认技术栈。后续如果公司基础平台有强制版本，只调整基础设施适配，不改变合同业务边界。

## 1. 技术栈定版

| 层级 | 选型 | 说明 |
|---|---|---|
| 后端语言 | Java 17 | 企业长期支持版本，作为一期统一运行时 |
| 后端框架 | Spring Boot 3.x | 统一配置、Web、事务、健康检查和运行管理 |
| Web 层 | Spring MVC | 合同系统以管理型 API 和异步任务为主，不采用 WebFlux |
| 数据访问 | MyBatis-Plus | 复杂查询和权限过滤保留手写 SQL 能力 |
| 数据库 | 云 MySQL 8.x 兼容数据库 | 使用托管数据库，不自建数据库服务器 |
| 缓存 | Redis | 缓存、幂等键、短期锁和任务辅助状态，不保存唯一业务事实 |
| 异步任务 | 消息队列优先；无统一组件时使用任务表+调度器 | AI、审批、文件任务异步执行和补偿 |
| 数据库迁移 | Flyway | 迁移脚本纳入版本控制，不能手工直接改生产表 |
| API 文档 | OpenAPI 3 | 生成接口文档和前后端联调模型 |
| 参数校验 | Jakarta Bean Validation | DTO 参数校验与业务前置校验分层 |
| 认证 | OAuth2/OIDC 或公司统一 SSO | 不在合同系统重复建设登录 |
| 权限 | 复用 HR 主系统 RBAC 和数据范围 | 合同系统补充合同类型、模板、字段和合同级授权 |
| 前端 | Vue 3 + TypeScript | 管理后台和合同业务页面 |
| UI | Element Plus 或公司统一组件库 | 优先复用公司组件库 |
| 部署 | Docker 镜像 + 公司部署平台 | 本地、测试、预生产、生产配置隔离 |

## 2. 架构形态

一期采用**模块化单体**：一个 Java 应用内按领域模块隔离，模块之间通过应用服务和内部接口交互。

```text
contract-app
  ├─ 合同核心
  ├─ 模板与类型
  ├─ 正文版本
  ├─ 交易对方引用
  ├─ 附件文件
  ├─ AI 任务
  ├─ 外部审批
  ├─ 履行与收付款
  ├─ 权限与审计
  └─ 外部 Adapter / Mock
```

不在一期拆微服务的原因：合同状态、权限、版本和审计关联紧密，模块化单体更容易保证事务一致性和开发效率。AI、文件和任务处理可以通过异步 Worker 扩展，达到性能瓶颈后再独立部署。

如果项目规模较小，也可以先使用单 Maven 模块，但包结构必须保持同样的领域边界，不能把所有代码放入一个 `controller/service/mapper` 平铺目录。

## 4. 依赖规则

- `api` 只负责请求、响应、参数校验和权限上下文，不写业务规则。
- `application` 负责用例编排、事务、幂等和权限调用。
- `domain` 负责合同状态机、版本规则和核心业务约束，不依赖第三方 SDK。
- `infrastructure` 负责 MyBatis、Redis、任务表和审计持久化。
- `integration` 负责外部系统 Adapter；每个 Adapter 必须同时有真实接口实现和 Mock 实现的接口位置。
- `job` 负责轮询、回调处理、重试、补偿和过期任务处理。
- 前端和业务服务只能依赖合同系统 API，不能直接访问 Dify、文件服务或审批系统。

## 5. 数据库连接与迁移

- 数据库设计只采用 `D:\project\hr-contract\数据库表\合同管理.docx` 的当前表结构；不从历史 Markdown 或增量方案推断表数量和字段。
- 正式开发前将表结构转换为 Flyway 初始迁移脚本；不根据旧归档 Markdown 重建表。
- 迁移脚本只允许向前追加版本，禁止修改已执行的生产脚本。
- 云数据库连接使用私网或安全连接，账号按读写、迁移和只读监控分离。
- 连接池、事务隔离级别、慢查询阈值、字符集和时区在环境配置中固定。
- Redis 只存缓存和短期控制信息，合同、正文、AI 结果和审计以数据库为准。

## 6. 统一 API 约定

请求上下文：

```text
Authorization
X-Request-Id
X-Idempotency-Key（写操作必填）
X-Api-Version
```

统一响应：

```json
{
  "code": "0",
  "message": "success",
  "data": {},
  "request_id": "request-id"
}
```

分页统一返回 `items`、`page`、`page_size`、`total`。错误至少区分认证失败、无权限、参数错误、状态冲突、版本冲突、外部依赖失败、任务失败和系统异常。

## 7. 前端初始化结构

```text
frontend/
  src/
    app/                 路由、布局、登录态、全局异常
    api/                 合同系统 API 封装
    pages/               工作台、台账、创建、详情、审批、系统配置
    modules/             合同、交易对方、附件、AI、审批、履行
    components/          表格、表单、状态、版本、权限组件
    stores/              当前用户、权限、页面状态
    types/               API 类型和领域显示模型
    utils/               日期、金额、错误和文件处理
```

前端第一轮使用 Mock API 完成交互原型，API 模型确定后切换真实后端接口；不在页面中复制第三方接口模型。

## 8. 工程初始化顺序

### 8.1 初始化阶段

1. 创建 Java 17 + Spring Boot 3.x Maven 工程。
2. 配置统一响应、全局异常、日志、请求 ID 和参数校验。
3. 接入云 MySQL 开发库，配置 Flyway。
4. 接入 Redis 和任务调度/消息组件。
5. 建立认证和权限上下文的 Mock。
6. 建立文件、审批、交易对方和 AI Provider 的 Mock Adapter。
7. 创建 Vue 3 + TypeScript 前端工程和 Mock API。

### 8.2 第一业务切片

后端：合同创建、类型读取、草稿保存、台账查询、详情查询、权限过滤、乐观锁和审计。

前端：合同台账、合同创建表单、草稿编辑、详情基础布局、状态动作和保存反馈。

验收：选择类型 → 填写通用/扩展字段 → 保存草稿 → 台账查询 → 进入详情 → 再次编辑 → 审计可查。

### 8.3 后续切片

1. 正文版本和文件附件。
2. AI 解析 Mock 和人工确认。
3. AI 审查 Mock 和法务确认。
4. 审批 Mock、回调、驳回、撤回和转交。
5. 签署文件、生效、履行、收付款和终止。
6. 变更、补充协议、权限细化和商用加固。

## 9. 商用基础要求

- 生产密钥进入配置中心或密钥管理服务，不进入仓库。
- 日志不得记录合同原文、身份证号、薪资、密钥或完整 AI 输入。
- 所有外部调用记录耗时、结果、错误原因和关联业务 ID。
- API、任务、数据库和文件操作都要有监控指标和告警。
- 测试、预生产和生产使用不同数据库、Redis、文件空间和外部凭证。
- 必须有数据库备份恢复、任务补偿、外部服务降级和版本回滚方案。

## 10. 本方案待确认项

以下只涉及公司基础设施接入，不改变已确定的一期产品范围：

- 公司是否已有 Java 17 或 Spring Boot 3.x 统一父工程。
- 公司统一 MyBatis/MyBatis-Plus、认证、权限、日志和异常规范。
- 云 MySQL 的具体厂商、版本、网络和备份策略。
- Redis、消息队列、任务调度和配置中心的公司标准。
- 前端统一组件库和登录集成方式。
