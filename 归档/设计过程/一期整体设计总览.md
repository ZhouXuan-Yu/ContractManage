# 通用合同管理系统一期整体设计总览

> 版本：V1.0
>
> 定位：一期可商用 MVP 的统一设计蓝图
>
> 说明：一期、二期、三期产品范围已经确定。本文件是一期整体设计总览，后续开发按此蓝图实施，不再反复拆分和重新定义产品范围。

## 1. 名称和概念

### 1.1 产品名称

产品叫：**通用合同管理系统**。

### 1.2 AI 专家体

“合同 AI 专家体”是本系统中的 AI 子能力，不是独立产品，也不是独立一级导航。它包含两项能力：

- 合同解析：从合同原文中抽取结构化字段、条款、标的和收付款计划。
- 法律风险审查：按合同类型、我方角色和审查视角识别风险，输出风险等级、原文依据、理由和建议。

AI 专家体的业务规则在 `AI专家体需求设计.md`；一期可以使用 Dify 私有化承载工作流，但合同系统通过 AI Provider 适配层接入，不能把业务代码写死到 Dify。

### 1.3 合同中心和合同中心区

- 合同中心：系统一级导航和业务工作区。
- 合同中心区：统一文件服务内为本系统分配的专属存储空间。
- 前者负责业务和页面，后者负责实际文件保存；两者不能混用。

## 2. 一期产品范围

### 2.1 一期包含

- 合同大类、合同类型、合同子类型和类型扩展字段。
- 合同模板、模板版本、变量映射和模板生成草稿。
- 合同创建：模板起草、文件导入、手工录入、外部系统同步的统一入口。
- 合同正文版本、原始文本、附件、签署文件和导出快照。
- 交易对方统一引用：客户、供应商、合作方、咨询机构等都是合同关系角色，不是独立主体模块。
- 我方主体引用、我方角色和关键时点信息。
- 合同生命周期：草稿、待签署、履行中、已完成、已终止、作废。
- 外部审批适配、审批状态、审批配置快照、回调和补偿；开发阶段使用 Mock。
- AI 解析、AI 法律风险审查、人工确认、重试和版本追溯；开发阶段使用 Mock，随后接 AI Provider。
- 履行事项、收付款计划、交付验收和履行记录。
- 变更和补充协议，必须从原合同发起并使用独立审批流。
- 工作台、合同台账、合同详情、审批工作台和系统管理。
- 权限、数据范围、合同类型权限、模板权限、字段权限、合同级授权和审计。

### 2.2 一期不做

- 客户或供应商主数据管理页面。
- 合同系统自建文件服务器或对象存储。
- 合同系统自建审批引擎。
- AI 自动审批、自动签署、自动改变合同状态或自动确认业务字段。
- 知识图谱。
- 二期统计增强、金额分级审批、多组织范围叠加、完整多币种折算和主体智能合并。
- 三期电子签章、归档借阅、智能续约和更复杂的 AI 能力。

## 3. 页面和导航总设计

```text
合同中心
  ├─ 工作台
  ├─ 合同台账
  └─ 履行与收付款

合同统计【二期】

系统管理
  ├─ 合同分类配置
  ├─ 合同模板配置
  ├─ 我方主体配置
  ├─ 外部连接配置
  └─ 权限与审计
```

审批工作台是合同详情和审批功能的统一工作区；合同创建、AI、审批关联、签署、变更和附件是流程页、详情页签或动作入口，不重复建设一级菜单。

### 3.1 页面职责唯一化

| 页面 | 唯一职责 | 不承担 |
|---|---|---|
| 工作台 | 指标、待处理事项和入口 | 完整合同查询 |
| 合同台账 | 合同查询、筛选、批量操作和导出 | 完整合同编辑 |
| 合同创建 | 新建和草稿编辑 | 审批、履行和审计管理 |
| 合同详情 | 单份合同完整业务上下文和下一步动作 | 主体主数据维护 |
| 审批工作台 | 待办、已办、我发起和审批状态 | 自建审批流程引擎 |
| 系统管理 | 类型、模板、连接、权限和审计配置 | 日常合同业务操作 |
| 交易对方选择 | 查询并引用外部主体 | 客户/供应商主档案管理 |

### 3.2 合同详情页签

概览、正文与版本、条款与履行、收付款、智能与审批、附件与变更、操作记录。页签按权限和是否有业务内容动态显示，空页签不显示。

## 4. 统一业务模型

### 4.1 合同核心

合同由通用底座和类型扩展组成：

```text
合同
  ├─ 分类：大类 / 类型 / 子类型 / 配置版本
  ├─ 我方：我方主体 / 我方角色
  ├─ 对方：外部主体引用 / 当前合同关系
  ├─ 内容：正文版本 / 原始文本 / 条款 / 标的
  ├─ 履行：履行事项 / 收付款计划 / 验收
  ├─ 智能：解析任务 / 审查任务 / 人工确认结果
  ├─ 审批：外部实例 / 审批历史 / 配置快照
  ├─ 文件：原始文件 / 签署文件 / 附件 / 导出快照
  └─ 追溯：版本、变更和操作审计
```

### 4.2 交易对方

客户、供应商、合作方等统一称为交易对方；关系由具体合同表达：

```text
交易对方 + relationship_role
  ├─ customer：对方购买我方产品/服务
  ├─ supplier：对方向我方提供产品/服务
  ├─ partner：双方合作开展项目
  ├─ consultant：对方提供咨询服务
  └─ other：其他合同关系
```

合同系统保存 `source_type + external_id`、必要展示信息和关键时点快照，不复制外部主体主档案。

### 4.3 状态分离

```text
合同业务状态：草稿 → 待签署 → 履行中 → 已完成
                         └→ 草稿（撤回签署）
草稿/待签署 → 作废
履行中 → 已终止

审批状态：未提交 → 审批中 → 通过 / 驳回 / 撤回
AI解析状态：未发起 → 处理中 → 待确认 / 已完成 / 失败
AI审查状态：未发起 → 处理中 → 待法务确认 / 已完成 / 失败
履行状态：未开始 → 履行中 → 已完成 / 已终止
```

审批和 AI 不占合同业务状态；所有状态转换由后端校验权限、当前状态、版本和前置条件。

## 5. 端到端业务流程

```text
选择合同类型和模板/导入文件/手工录入
  → 引用我方主体和交易对方
  → 填写通用字段和类型扩展字段
  → 保存草稿和正文版本
  → 发起 AI 解析并人工确认
  → 发起 AI 法律审查并由法务确认
  → 提交外部审批并锁定关键内容
  → 审批通过进入待签署
  → 上传签署文件并确认生效
  → 履行交付、验收和收付款
  → 完成/终止
  → 从原合同发起变更或补充协议
```

所有外部结果必须幂等同步；失败进入可见的失败、待同步或待人工处理状态，不伪造成功。

## 7. 外部系统边界

```text
HR/组织系统：员工、组织、岗位和数据范围
外部交易对方主数据系统：客户、供应商、合作方等交易对方
我方主体/法人系统：我方公司和法人主体
统一文件服务：合同中心区的物理文件、上传、预览、下载和短期链接
统一审批系统：流程、节点、审批人、审批页面和流转
AI Provider：解析、审查工作流和模型调用
```

交易对方可能来自一个或多个外部系统，合同系统不预设客户和供应商对应几个系统；内部统一通过交易对方 Adapter 接入。所有外部依赖都必须有 Mock 和 Adapter，真实接口提供后只替换 Adapter。

## 8. AI 专家体设计

### 8.1 AI 架构

```text
合同系统 Java
  → AI Provider 适配层
    → Mock / Dify / 直接模型 API / 其他平台
      → 解析工作流或法律审查工作流
        → 模型 + 审查知识库
```

合同系统负责任务、版本、权限、Schema、重试、人工确认和审计；AI 平台不负责合同状态、审批、签署和最终业务确认。

### 8.2 Skill、知识库、知识图谱

- Skill：需要，但作为解析和审查工作流中的规则/工具能力，不一期建设独立 Skill 管理平台。
- 知识库：需要。用于法律法规、公司制度、审查规则和标准条款检索；资料必须有来源、版本、生效日期和适用范围。
- 知识图谱：一期不需要。等后续需要跨合同关系、法规影响范围、义务网络和智能续约时再建设。

### 8.3 AI 结果控制

- 结果绑定合同 ID、正文版本 ID、任务 ID、Schema 版本和 Provider/工作流版本。
- 用 `content_hash + schema_version + task_type` 做幂等判断。
- Schema 校验失败、超时、低置信度和无原文依据必须进入失败或待人工确认。
- 已人工确认结果不得被后续任务直接覆盖。
- AI 只提供建议和结构化初稿，不能自动修改合同业务状态。

## 9. 技术架构

### 9.1 技术栈

```text
Java 17
Spring Boot 3.x
Spring MVC
MyBatis-Plus
云 MySQL 8.x 兼容数据库
Redis
公司标准消息队列/任务调度
Flyway
OpenAPI 3
Vue 3 + TypeScript
模块化单体
```

优先复用公司基础认证、权限、组织、日志、消息和部署平台。

### 9.2 工程边界

```text
backend
  api                 请求、响应、校验
  application         用例、事务、幂等
  domain              合同聚合和状态规则
  infrastructure      MyBatis、Redis、任务和审计持久化
  integration         交易对方、文件、审批、AI Adapter
  job                 轮询、回调、重试和补偿
  test                契约、集成和业务测试

frontend
  pages               工作台、台账、创建、详情、审批、系统管理
  modules             合同、交易对方、附件、AI、审批、履行
  api                 合同系统 API
  permissions         页面、按钮和字段展示控制
```

一期采用模块化单体，不先拆微服务；通过异步任务隔离 AI、文件和审批处理。

## 10. 权限和商用安全

权限判定链路：

```text
菜单权限
 → HR 数据范围
 → 合同类型/子类型权限
 → 模板权限
 → 字段权限
 → 合同级临时授权
 → 动作和状态校验
```

- 前端隐藏按钮不能替代后端权限校验。
- 敏感字段支持可见、脱敏、只读和编辑控制。
- 密钥密文保存，不进入前端和普通日志。
- 合同原文、身份证号、薪资和 AI 完整输入不得写入普通日志。
- 文件预览和下载先校验合同权限，再申请短期链接。
- 审计记录覆盖合同、版本、AI、审批、文件、导出、授权和配置变更。
- 生产、测试和本地环境使用独立数据库、Redis、文件空间和外部凭证。
- 必须具备备份恢复、任务补偿、外部故障降级、监控告警和回滚方案。

## 11. 一期测试范围

### 11.1 主流程

- 手工创建、模板创建、文件导入和草稿保存。
- 交易对方引用、主体停用和关系角色选择。
- 正文版本、类型扩展字段和乐观锁。
- AI 解析、人工确认、AI 审查和法务确认。
- 审批提交、通过、驳回、撤回、转交和重复回调。
- 签署生效、履行、收付款、完成和终止。
- 变更和补充协议独立审批、生效和历史版本。

### 11.2 异常和安全

- 重复请求、回调乱序、旧版本结果晚到。
- 外部系统超时、不可用、字段缺失和错误响应。
- AI Schema 错误、低置信度、超时、重试耗尽和人工重发。
- 多人编辑、版本冲突、审批锁定和撤回重提。
- 无权查看合同、敏感字段、附件、AI 结果和导出文件。
- 文件哈希不一致、病毒扫描失败、链接过期和重复上传。
- 数据备份恢复、审计完整性和生产配置隔离。

## 13. 当前开发入口

整体设计完成后，第一批正式开发工作是：

1. 从当前 `合同管理.docx` 读取实际表结构，生成数据库迁移基线。
2. 按本总览确定第一切片 API 和内部领域模型。
3. 完成交易对方、权限和审计的基础 Mock。
4. 实现合同创建、草稿、台账和详情的前后端闭环。

不在这一步重新讨论一期范围、数据库表数量或客户/供应商是否是独立模块。
