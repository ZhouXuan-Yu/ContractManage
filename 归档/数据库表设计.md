# 合同管理系统 — 数据库表设计（历史草案，待按新需求重做）

> 版本：历史 V1.0
>
> 警告：本文档仍包含旧的商务合同、固定合同类型、本地交易对方和本地审批配置设计，暂不作为开发依据。新数据库设计必须以通用合同需求、当前思维导图和《人力资源管理系统数据库设计文档4》为准。
> 遵循《人力资源管理系统数据库设计文档4》规范：主键 `id` BIGINT 雪花非自增、逻辑删除 `deleted`、枚举 `TINYINT`、索引 `uk_`/`idx_`。
> 所有表均含公共审计字段（不再逐表重复列出）：`create_by / create_time / update_by / update_time / deleted`。

## 公共审计字段（每张表尾部都有）

| 字段 | 类型 | 说明 |
|---|---|---|
| create_by | BIGINT | 创建人 |
| create_time | DATETIME | 创建时间 |
| update_by | BIGINT | 更新人 |
| update_time | DATETIME | 更新时间 |
| deleted | TINYINT | 逻辑删除：0 否 / 1 是 |

## 设计约束（商用必需）

- 关键表建议增加 `version` 或使用主表 `content_version` 做乐观锁；更新必须携带客户端读取版本，版本不一致时拒绝覆盖。
- `t_contract_attachment.change_id` 与 `t_contract_change.contract_id` 必须校验属于同一原合同；补充协议附件不能只挂原合同而不挂变更记录。
- 金额、币种和收付款方向必须成组校验；金额统一使用 `DECIMAL`，禁止使用浮点数。多币种折算字段留到二期，不在一期伪造汇率口径。
- 所有唯一约束都要结合 `deleted` 设计，避免逻辑删除后的编号/信用代码无法复用；企业信用代码和个人身份证号还应按主体类型做后端校验，敏感字段脱敏展示。
- AppSecret、身份证号等敏感数据不得写入操作日志的前后快照；日志和导出文件必须按权限控制并记录访问行为。
